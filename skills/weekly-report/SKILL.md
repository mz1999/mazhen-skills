把**当前会话刚完成的任务**总结成给领导的汇报条目，任何领域的工作都适用（功能、修复、版本发布、文档、调研、工具、迁移……）。好汇报只有两条判据：领导**看得懂**（不陷入实现细节），有**掌控感**（清楚进展到哪、这件事的价值是什么）——写领导最想了解的，而不是做的人最想交代的。素材 = **当前会话**的工作（任务做完当场召唤）——**不跨会话汇集**其他任务；当前仓库的代码、git 提交历史、文档可按需扫描，补齐数字、链接、覆盖范围。

## 步骤

1. **列素材清单**：每个交付物一行——名称、实测数字、链接、覆盖范围（平台/版本/环境矩阵）。上下文经压缩就以摘要为准；关键数字、链接、覆盖范围缺出处或缺细节时，查当前仓的文件与 git 历史补齐。跨仓/跨会话的任务，其他段用 git 历史找回，每个仓至少一行。
2. **定定位**（定位错 = 重写）：回答两句——① 这条成果在**能力层**是什么：把事件层改写成能力层（某次报障/需求只是**暴露途径**，成果是底层补齐了通用能力，应用方零改动受益）；② 挂在**项目全景**的哪条线上，答句形状「已有 X，本次补上 Y」。价值放大器占了就写：**里程碑**（首个、首次、首批）、**机制化**（此后自动、纳入流程长期执行）。
3. **写条目**：加粗导语（成果一句话）+ 1–3 句支撑。支撑句至少带一个实物（数字/具体名称/链接）；受益场景写成「**此前 X，现在 Y**」（此前无法快照、失败随机出现……现在自动识别、零改动受益）。用户给了上次周报尾部或参考样式就**续其编号、口吻、粒度**；没给就按内置样例的口吻与粒度自成条目。写完对照下节七条规则逐条自检——每条在成稿上有落点或明确不适用。
4. **收尾**：重磅条目（版本发布、大能力上线）附一句话版；口径说明、证据映射等附加块明确标注「不进周报」。

## 取舍规则

- **删过程**：复核轮次、commit、内部机制名——领导不可感知的一律删（「多轮独立复核，领导就没必要知道」）；编号裸写删、挂成链接留。外部里程碑**状态**相反要写明：待评审、已合入、已上架、纳入流程。
- **留实物**：具体名称（写「五类服务」就要点名是哪五类）、数字、可点开的链接（内部仓库/文档站；材料归档后给归档链接）。删过程 ≠ 抽象到没内容。
- **术语前置**：标识性术语保留并前置——cgroups、UNIX domain socket、file lock——一看大概就明白改了什么。机理默认不给；只有机理就是价值本身时（故障形态）才展开成支撑句。
- **数字口径**：一律取实测口径。引用官方宣称前先经实测复核——成立写「经实测复核成立」，不成立剔除并写明剔除动作。
- **阻塞显式化**：需协调事项单独成条/节——写清「请协调什么」+ 兜底句；上期阻塞本期解决写「清零/打通」，形成闭环。决策钩子同形：调研结论带「可安排讨论」、梳理产出带「形成问题清单」，给领导下一步抓手。
- **敏感边界**：对内周报可写产品线动机与未公开规划；材料可能流出（外发、上报更上层、跨范围转发）时提示删敏感指代。
- **篇幅**：每条 2–4 句，拿不准往短压。整周版（任务密集期、跨多任务）= 分节 + 下周计划 + 一句话总结；分节用**稳定线名**，跨周沿用同一节名，让领导按线追进展。
